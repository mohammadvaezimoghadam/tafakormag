# راهنمای جامع دواپس: پشتیبان‌گیری، بازیابی اضطراری و دیپلوی بدون قطعی
**پروژه پلتفرم تفکر (Tafakor Mag / Avapardaz)**  
**تهیه‌شده بر اساس استانداردهای مهندسی SRE / DevOps**  
**تاریخ تدوین:** ۱۴۰۵/۰۸/۰۸ (2026-10-30)

---

## ۱. اصل طلایی: پایداری ۱۰۰٪ و ممنوعیت قطعی (Zero-Downtime)

> [!CAUTION]
> **قانون اول دواپس:** هیچ‌گاه برای اعمال تغییرات یا دیپلوی، دستور `docker compose down` را اجرا نکنید!
> خاموش کردن کل داکر باعث قطع شدن دیتابیس، ارور ۵۰۲ برای کاربران و شکست تراکنش‌های فعال می‌شود.

در معماری کانتینری تفکر:
- کدهای پایتون به صورت Volume به کانتینر متصل هستند؛ نیاز به بیلد مجدد ندارند.
- دیتابیس PostgreSQL باید همیشه روشن و در حالت `healthy` بماند.
- تنها سرویسی که هنگام تغییرات UI نیاز به کامپایل دارد، کانتینر **فرانت‌اند (Vue)** است.

## ۲. دستورالعمل پشتیبان‌گیری دیتابیس (Database Backup)

### ۲.۱. گرفتن بک‌آپ فشرده و زمان‌دار
```bash
mkdir -p ~/backups
docker exec -t tafakor_db pg_dump -U postgres tafakor | gzip > ~/backups/backup_$(date +%Y%m%d_%H%M%S).sql.gz
```

### ۲.۲. اعتبارسنجی سلامت بک‌آپ (حیاتی!)
هیچ‌گاه به صرف ساخت فایل اعتماد نکنید. حجم فایل را بررسی کنید:
```bash
ls -lh ~/backups
```
- **حجم سالم:** معمولاً ده‌ها کیلوبایت تا چندین مگابایت (مثلاً `91K` به بالا).
- **هشدار فایل خراب (تله ۱۴۱ بایتی):** اگر فایل حدود ۱۴۰ تا ۲۰۰ بایت بود، یعنی دستور با خطا مواجه شده و gzip متن ارور لینوکس را ذخیره کرده است! با دستور زیر محتوای ارور را بخوانید:
  ```bash
  zcat ~/backups/backup_xxxx.sql.gz
  ```

## ۳. سناریوی بازیابی اضطراری در شرایط فاجعه (Disaster Recovery / Restore)

اگر دیتابیس خراب شد، تیبل‌ها ناخواسته پاک شدند یا مشکلی پیش آمد، این فرآیند دو مرحله‌ای دیتابیس را در کمتر از ۱۰ ثانیه دقیقاً به حالت قبل بازمی‌گرداند:

```bash
# گام ۱: پاکسازی کامل اسکیما جهت رفع تداخل کلیدهای تکراری
docker exec -t tafakor_db psql -U postgres -d tafakor -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"

# گام ۲: تزریق مستقیم فایل بک‌آپ فشرده به دیتابیس
gunzip -c ~/backups/backup_YYYYMMDD_HHMMSS.sql.gz | docker exec -i tafakor_db psql -U postgres -d tafakor > /dev/null
```
*(نکته فنی: در دستور دوم حتماً از سوییچ `-i` برای تزریق ورودی استفاده می‌شود).*

## ۴. چرخه استاندارد دیپلوی و آپدیت کد (Deployment Workflow)

### گام ۱: دریافت آخرین کدها از گیت
```bash
cd ~/tafakormag
git pull origin main
```

### گام ۲: اعمال مایگریشن‌های دیتابیس (بدون قطعی)
```bash
docker exec -t tafakor_backend python manage.py migrate
```

### گام ۳: نوسازی کارگرهای پایتون (Graceful Reload)
برای اینکه تغییرات کدهای پایتون در سرور Gunicorn اعمال شوند:
```bash
docker restart tafakor_backend
```

### گام ۴: بیلد اختصاصی فرانت‌اند (فقط در صورت تغییرات وب)
> [!IMPORTANT]
> به دلیل وجود تحریم‌ها و کندی مخازن PyPI برای پروکسی و ربات‌ها، **هرگز دستور کلی `docker compose up -d --build` را نزنید!**  
> فقط و فقط فرانت‌اند را هدف بگیرید:
```bash
docker compose --profile vue build frontend
docker compose --profile vue up -d frontend
```

### گام ۵: تست دود و راستی‌آزمایی (Smoke Test)
```bash
# بررسی سرویس پست‌ها و فیلتر آیه قرآنی
curl -s "http://localhost:8085/api/notes/?ayah=2:255"

# بررسی فرانت‌اند
curl -I http://localhost:8085/
```

## ۵. رفع کش مرورگر کلاینت (Hard Refresh)
پس از بیلد فرانت‌اند، کلاینت‌ها برای مشاهده سریع تغییرات CSS و JS باید کش مرورگر را خالی کنند:
- ویندوز/لینوکس: `Ctrl + F5` یا `Ctrl + Shift + R`
- مک: `Cmd + Shift + R`
